# Ron-1

رون-1 مساعد لغوي محلي داخل المتصفح. **أوزان SmolLM2 هي النموذج الذي ينفذ الاستدلال**؛ أما كود Ron-1 فيوفّر المحادثة، وإدارة السياق، وتشغيل النموذج محليًا، والتخزين والاختبارات.

## نموذج التشغيل الحالي

- النموذج: SmolLM2-135M-Instruct بصيغة ONNX Q4 المناسبة لمسار WASM/CPU.
- `ron-model-worker.js`: يحمل tokenizer والنموذج ويولّد الردود داخل Web Worker.
- `weights/ron1-q4-*.bin` و`weights/ron1-q4-manifest.json`: أجزاء الأوزان وبيان أحجامها، وتُنشر ضمن حزمة Ron-1 على GitHub Pages.
- `vendor/transformers/` و`models-v2/`: محرك الاستدلال المحلي وبيانات النموذج.
- `sw.js`: يخزّن الأجزاء التي تم تنزيلها بنجاح لإعادة استخدامها لاحقًا.

أوزان Q4 الحالية يبلغ حجمها **180,581,125 بايت (نحو 180.6 MB)** ومقسمة إلى خمسة أجزاء؛ يُنشئ GitHub Actions بيانًا يحدد الحجم والترتيب ثم يضمّ الأجزاء إلى مخرجات الموقع والمستودع. المتصفح يطلب هذه الأجزاء من **نفس أصل Ron-1**؛ لا يستدعي Hugging Face ولا GitHub Releases ولا خادم استدلال خارجي أثناء المحادثة. الأجزاء ملفات الأوزان الفعلية التي يحمّلها محرك رون، وليست نموذجًا بديلًا على خادم بعيد. أول زيارة تحتاج تنزيلها، ثم يحاول المتصفح تخزينها لإعادة الاستخدام.

## لماذا تغيرت الصيغة؟

النسخة السابقة استخدمت Q4F16 على WASM وظهرت مشكلة تعارض نوع Tensor بين float16 وfloat32 أثناء التوليد. المسار الجديد يختار Q4 بدل Q4F16 على WASM ويضبط بيانات KV cache على float32، مع manifest يتحقق من اكتمال كل جزء وإجمالي الأوزان. هذا تغيير في ملف النموذج وإعدادات الاستدلال، وليس مجرد رسالة خطأ مختلفة.

## التدريب وتطوير رون

يوجد مسار تطوير منفصل في `training/` لتخصيص نموذج SmolLM2 باستخدام LoRA ثم دمج الأوزان. ناتج التدريب لا يصبح تلقائيًا نموذج المتصفح: يجب تصديره إلى ONNX، وتكميمه إلى صيغة مناسبة، واختباره على المتصفح قبل نشره. لم يتم الادعاء بأن Ron-1 دُرّب من الصفر؛ الأوزان الحالية أوزان SmolLM2 جاهزة يستخدمها رون كأساس.

## التحقق

GitHub Actions يفحص صياغة JavaScript، وإعدادات Q4، وخطوات تقسيم الأوزان وإنشاء manifest، وعقد التشغيل والتخزين. نجاح الفحوصات لا يغني عن اختبار فعلي للتوليد على Android. لا أعتبر خطأ float16 محلولًا نهائيًا حتى ينجح توليد رد حقيقي في المتصفح بعد نشر هذا التغيير.
